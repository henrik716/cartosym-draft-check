Rendering passes, zOrder and casing: test cases

Cases for #212: how viz.pass, feature.pass, zOrder, casings, labels and nested rules decide what is drawn on top. Cases 01 to 08 are Maxime Collombin's (pycartosym examples/passes), with marker: null; added to each top-level rule so that no default Dot is drawn; 09 to 13 are the others listed on #197. Where the text is open, marked open in the text, the draft renderer draws each reading. All are drawn on the same roads, railway and zone, kept small so that other software can redraw them exactly; Annex C examples 12 and 13 in #233 show the same mechanisms on a real map (roads and the railway at Otta). Each card links a render kit: the style in both encodings, one GeoJSON file per data layer, the view, the draft renderer's image and a README with what should be drawn (all in kit.zip). The draft renderer implements the text, so its image shows what the text says, not that the text is right. SLD/SE, MapLibre and QGIS versions are welcome as pull requests.

01-nested-override: Nested rules without a selector override each other#

// Nested rules without a selector are the same as removing their curly// brackets: the second overrides the first, only the white stroke remains.[kind = 'road']{   marker: null;   { stroke: { color: black; width: 5 px; }; }   { stroke: { color: white; width: 3 px; }; }}

What should be drawn. Each road is drawn once, with the white 3 px stroke. The two nested rules have no selector, so they merge into their parent and the second stroke replaces the first (#197, #200). No black shows.

02-toplevel-override: Top-level rules with the same selector override each other#

// Top-level rules with the same selector override one another as well:// identical to the single rule with the white stroke.[kind = 'road'] { marker: null; stroke: { color: black; width: 5 px; }; }[kind = 'road'] { marker: null; stroke: { color: white; width: 3 px; }; }

What should be drawn. The same as 01: both rules select every road, and the second rule's stroke replaces the first's. Each road has only the white 3 px stroke.

03-feature-pass: feature.pass: one feature at a time#

// Each feature is drawn with the black stroke, then with the white one,// before the next feature is drawn.[kind = 'road']{   marker: null;   [feature.pass = 0] { stroke: { color: black; width: 5 px; }; }   [feature.pass = 1] { stroke: { color: white; width: 3 px; }; }}

What should be drawn. Each road is drawn with its black 5 px stroke and then its white 3 px stroke, before the next road. Roads are drawn in data order (road 1, 2, 3), so at the crossing road 2's black edges cut across road 1's white line, and at the T-junction road 3's black end cuts into road 1's white line. The edges are 1 px wide, so the difference from 04 is small; style-wide.cscss is the same style with 12 px and 8 px strokes, where it shows clearly.

04-viz-pass: viz.pass: all features per pass#

// All the roads are drawn with the black stroke first, then all of them// with the white one: the white strokes cross over every black stroke.Roads{   marker: null;   [viz.pass = 0] { stroke: { color: black; width: 5 px; }; }   [viz.pass = 1] { stroke: { color: white; width: 3 px; }; }}

What should be drawn. Pass 0 draws the black 5 px strokes of all roads, pass 1 their white 3 px strokes. The white lines join at the crossing and at the T-junction, with no black across them. style-wide.cscss is the same style with 12 px and 8 px strokes, to compare with 03's.

05-casing: Built-in casing#

// Built-in casing, no passes needed.[kind = 'road'] { marker: null; stroke: { color: white; width: 3 px; casing: { color: black; width: 1 px; }; }; }

What should be drawn. Each road has a white 3 px stroke with a black casing 1 px beyond each side (5 px in all, #147). The roads have the same zOrder, so the casings of all roads are drawn before their main strokes: the crossing and the T-junction merge, and the map looks the same as 04.

06-rule-without-pass: A rule without viz.pass next to rules with one#

// A rule without viz.pass next to rules that have one: it applies in pass 0// only (settled in opengeospatial/cartographic-symbology#198), so the// background fill is drawn once, with the first pass.Zones { marker: null; fill: { color: lightGray; }; }Roads{   marker: null;   [viz.pass = 0] { stroke: { color: black; width: 5 px; }; }   [viz.pass = 1] { stroke: { color: white; width: 3 px; }; }}

What should be drawn. Pass 0: the light gray fill of the zone, with the default black 1 px stroke (the rule sets no stroke), and the black 5 px strokes of the roads. Pass 1: the white 3 px strokes of the roads. The Zones rule doesn't test viz.pass, so it is drawn in pass 0 only: a rule that doesn't test viz.pass is evaluated in every pass, but only a rule that tests it is drawn in a pass other than 0 (Jérôme on #207 and #211; #198).

07-feature-and-viz-pass: feature.pass inside a viz.pass#

// Both identifiers: for each viz.pass, each feature is drawn with its// feature.pass symbolizers in order.Roads{   marker: null;   [viz.pass = 0]   {      [feature.pass = 0] { stroke: { color: black; width: 7 px; }; }      [feature.pass = 1] { stroke: { color: white; width: 5 px; }; }   }   [viz.pass = 1] { stroke: { color: red; width: 1 px; }; }}

What should be drawn. Pass 0, one road at a time: its black 7 px stroke, then its white 5 px stroke (feature passes 0 and 1), so at the crossing road 2's black edges cut across road 1's white line, as in 03. Pass 1: the red 1 px line of every road, above all of pass 0 and unbroken at the crossing.

08-zorder: zOrder across data layers#

// zOrder reorders the features of one pass (here, rails above roads).Roads { marker: null; stroke: { color: gray; width: 4 px; }; zOrder: 0; }Rails { marker: null; stroke: { color: black; width: 2 px; }; zOrder: 1; }

What should be drawn. The railway (zOrder: 1) is drawn above the roads (zOrder: 0): the black 2 px line is unbroken where it crosses the gray 4 px roads (/req/core/z-order). view.json lists Rails before Roads, so without zOrder the roads would be drawn over the railway: only zOrder puts it on top. The roads join at the crossing and the T-junction, as they are all drawn before the railway.

09-center-line: Built-in casing and center line#

// Built-in casing and center line: within a zOrder, the casings of all roads// go beneath all main strokes, and the center lines of all roads on top of// them, so a joining road cuts neither (/req/casing/casing, /req/casing/center).Roads{   marker: null;   stroke: { color: #f5d76e; width: 10 px; casing: { color: #6b4f1d; width: 1.5 px }; center: { color: #6b4f1d; width: 1 px } };}

What should be drawn. Each road has a yellow 10 px stroke, a brown casing 1.5 px beyond each side and a brown 1 px center line. The casings of all roads are drawn first, then the main strokes, then the center lines: at the crossing and the T-junction the yellow strokes join with no casing across them, and the center lines run through (road 2's over road 1's). style-passes.cscss writes the same order with three visualization passes and draws the same image (the build checks this).

10-labels-pass: Labels and visualization passes open in the text#

Open question. Labels are drawn "as a separate pass on top of all styled vector features and coverages" (/req/labels/label). With visualization passes, is that after the last pass, or at the end of the pass that draws the label? The label is set in a rule that doesn't test viz.pass, so it applies in both passes: is it drawn once?

// Labels on roads drawn in two visualization passes. Labels are drawn// "as a separate pass on top of all styled vector features" (/req/labels/label):// after the last visualization pass, or at the end of the pass that sets them?Roads{   marker: null;   label: { elements: [ Text { text: name, alignment: center middle,                               font: { face: 'Arial', size: 11, bold: true, color: black } } ] };   [viz.pass = 0] { stroke: { color: black; width: 12 px }; }   [viz.pass = 1] { stroke: { color: white; width: 8 px }; }}

What should be drawn. Pass 0: the black 12 px strokes of the roads; pass 1: their white 8 px strokes; then the labels, black on the white roads, on top of everything. Each label is drawn once, although its rule applies in both passes. Road 2's label would overlap Road 1's, so only Road 1's is drawn (/rec/labels/overlap; both have the same priority, and Road 1 comes first).

11-feature-pass-minus-one: A bridge in feature pass -1#

// A railway bridge over a road, as in Annex C example 13. zOrder raises the// bridge (z_order 2) over the road (zOrder 1). In feature pass -1 the bridge// gets a wide white line with a dark casing; in pass 0 the railway itself is// drawn on it.Roads { marker: null; zOrder: 1; stroke: { color: #f5d76e; width: 8 px; casing: { color: #6b4f1d; width: 1 px } }; }Rails{   marker: null;   zOrder: z_order;   stroke: { color: #333333; width: 3 px };   // After the rule above, so that it overrides the railway's stroke in pass -1   [feature.pass = -1 and bridge = true] { stroke: { color: white; width: 9 px; casing: { color: #333333; width: 1 px } }; }}

What should be drawn. The roads and the two ground pieces of the railway (z_order 1) are at zOrder 1: the roads' casings first, then the main strokes in data layer order, so the railway crosses road 1 on the level, over it. The bridge piece has z_order 2, so it comes after everything at zOrder 1: first its feature pass -1, a white 9 px line with a dark casing 1 px beyond each side, covering road 2 beneath, then its pass 0, the black 3 px railway on top. At the bridge's ends, the round caps of the white line and its casing (/req/vector/stroke) show as half circles around the railway.

12-shared-zorder: Two data layers sharing a zOrder open in the text#

Open question. /req/casing/casing draws "the casings of all features with the same zOrder" beneath "the main strokes of all those features". Does that include the features of other data layers? The painter's algorithm in clause 7 says so, but it is commented out of the published text; QGIS orders only within one map layer (kraftto on #212).

// Roads and a railway in two data layers with the same zOrder, both with// casings. "The casings of all features with the same zOrder" are drawn// beneath "the main strokes of all those features" (/req/casing/casing):// does that include the features of other data layers?Roads { marker: null; stroke: { color: #f5d76e; width: 8 px; casing: { color: #6b4f1d; width: 1.5 px } }; }Rails { marker: null; stroke: { color: white; width: 3 px; dashPattern: [ 6 px, 6 px ]; casing: { color: #333333; width: 1.5 px } }; }

What should be drawn. Roads and the railway have the same zOrder (the default). Reading "all features" across data layers: the casings of the roads and the railway are drawn first, then the main strokes in data layer order, roads then railway. Where the railway crosses a road, its white dashes lie on the yellow road with no dark casing across it, and no road casing cuts the railway.

13-translucent-passes: A translucent layer with visualization passes open in the text#

Open question. /rec/core/opacity-together applies the Symbolizer opacity to the parts of a feature together, "either for each feature or for all features of a data layer with the same zOrder drawn at once". With visualization passes, is that one group per pass, or one group for all of the layer's passes?

// A translucent road layer drawn in two visualization passes over a zone.// The Symbolizer opacity applies to the parts of a feature together// (/rec/core/opacity-together): for each pass, or for the layer's passes// together?Zones { marker: null; fill: { color: #5b8c5a }; }Roads{   marker: null;   opacity: 0.5;   [viz.pass = 0] { stroke: { color: black; width: 12 px }; }   [viz.pass = 1] { stroke: { color: white; width: 8 px }; }}

What should be drawn. Pass 0: the green zone (with the default black 1 px stroke), then the roads' black 12 px strokes at 50 % as one group, so they don't show through each other at the crossing. Pass 1: the roads' white 8 px strokes at 50 %, as a second group over the first, so the black shows through the white: light gray roads with dark edges, through which the zone shows.
